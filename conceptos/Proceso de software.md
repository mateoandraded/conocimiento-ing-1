# Proceso de software

**En una línea:** secuencia de actividades que lleva a producir un producto de software.

## Jerarquía (Pressman)
- **Proceso:** colección de actividades, acciones y tareas para crear un producto de trabajo.
- **Actividad:** objetivo amplio, aplica siempre (ej. comunicación con stakeholders).
- **Acción:** conjunto de tareas que produce un producto de trabajo importante (ej. diseño arquitectónico → modelo arquitectónico).
- **Tarea:** objetivo pequeño y bien definido con resultado tangible (ej. una prueba unitaria).

## 4 actividades fundamentales (Sommerville)
1. **Especificación** — qué se va a producir y sus restricciones.
2. **Desarrollo** — diseño y programación.
3. **Validación** — verificar que es lo que el cliente necesita.
4. **Evolución** — modificarlo según cambien las necesidades.

## 5 actividades del marco genérico (Pressman & Maxim)
**Comunicación → Planificación → Modelado → Construcción → Despliegue.**
(Truco: *"Con Plan Modelo, Construyo y Despliego"*.)

## Adaptación
El proceso no es una receta rígida: se adapta al problema, proyecto, equipo y cultura organizacional.

## SDLC / modelo de proceso
Un **modelo de proceso (SDLC)** es una representación simplificada de un proceso, desde una perspectiva (muestra parte de la información). Ver [[Modelos de proceso de software]].
