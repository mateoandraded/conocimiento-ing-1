Sección A
Sistema de Reservas y Gestión de Viajes
Los estudiantes de ingeniería de software de ESPOL han sido encomendados por una empresa líder en turismo,
NexaTour, para crear un sistema de reservas y gestión de viajes. El sistema debe permitir a los usuarios buscar
y reservar vuelos, hoteles, actividades y paquetes turísticos de forma eficaz. Por lo que puede contar con un
motor de búsqueda avanzado que permita filtrar resultados por precio, ubicación, comodidades y calificaciones
como mínimo. Además, necesita proporcionar detalles detallados sobre cada opción, que podría incluir
imágenes, descripciones y/o reseñas de otros usuarios. Las reservas se confirman instantáneamente,
proporcionando mensajes claros y detallados.
En cuanto a la adaptabilidad, el sistema debería poder evolucionar con las tendencias y tecnologías emergentes,
siendo capaz de incorporar nuevas funciones y actualizaciones sin problemas. La seguridad es prioritaria: se
necesitan medidas avanzadas para proteger los datos de los clientes y garantizar transacciones seguras.
NexaTour considera que el sistema podría ofrecer análisis en tiempo real para una toma de decisiones rápida y
eficiente. Esto implica manejar grandes volúmenes de datos de forma ágil, utilizando tecnologías como el
procesamiento en la nube para asegurar respuestas instantáneas a las consultas de los usuarios. Se requerirá
un sistema de seguimiento del rendimiento para evaluar la eficacia del sistema y realizar mejoras continuas.

Se recomienda altamente que la interfaz de usuario sea intuitiva y fácil de usar, permitiendo a los usuarios
realizar pagos seguros en línea. Una opción es que se pueda integrar con pasarelas de pago confiables y que
garantice la seguridad de las transacciones financieras. Los usuarios podrían hacer cambios en sus reservas,
como modificar fechas o agregar servicios adicionales, entre otros, de manera sencilla y sin complicaciones. El
sistema debería proporcionar un sistema de atención al cliente eficaz, lo que podría incluir chat en vivo y
consultas por correo electrónico para respuestas rápidas a las preguntas de los usuarios. La empresa ha oído
que la inteligencia artificial está en auge últimamente, por lo que están validando opciones para incursionar
también en esa área.
Para NexaTour, la satisfacción del cliente es primordial, por lo que podrían enfocarse en la experiencia del
usuario en lugar de las funcionalidades sociales dentro de la plataforma.
Para los administradores, el sistema debe ofrecer un panel de control que les permita gestionar las reservas,
verificar disponibilidad y ajustar precios según la demanda. Necesitaría generar informes detallados sobre las
ventas, tendencias y la satisfacción del cliente para facilitar la toma de decisiones empresariales.
NexaTour está segura de que estos requerimientos harán que el sistema de reservas y gestión de viajes sea
completo, infalible y proporcione una experiencia gratificante tanto para los usuarios como para los
administradores del sistema.
Procedimiento [80%]
1. Leer detenidamente los requerimientos del proyecto.
2. Identificar y subrayar las principales funciones y características que se esperan del sistema de reservas y
gestión de viajes. Utilizar alguna técnica para el levantamiento de requerimientos. (7 pts.).
3. Identificar a todas las partes interesadas involucradas en el sistema (8 pts.).
4. Encuentre ocho ambigüedades, conflictos u omisiones en el desarrollo del sistema de reservas y gestión de
viajes (15 pts.).
5. Especifique dos requerimientos funcionales del sistema por estudiante. Haga uso de MoSCoW [1] en su
especificación (25 pts.).
6. Defina dos requerimientos no funcionales que puedan ser identificados para el sistema descrito por
estudiante y explique por qué usted cree que estos requerimientos son apropiados para este sistema.
Especifique cómo podrían ser validados dichos requerimientos. Para cada requerimiento especifique el tipo
de requerimiento no funcional usando la categorización de tipos de requerimientos no funcionales de
Sommerville (25 pts.).
Desafío [20%]
Redactar 5 historias de usuario basadas en los requerimientos funcionales y no funcionales utilizando el formato
Connextra [1] (20 pts.).
